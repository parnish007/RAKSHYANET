Innovation & impact · prior art

Three things already exist. None of them close the loop.

Humanitarian logistics software
Sahana Eden, HELIOS, LSS, SUMA, LogistiX

Inventory, consignment tracking, 4W coordination matrices. A published review of these packages found they do not model routing or resource scheduling at all — they record what was decided, they do not decide it.

Logistics Cluster coordination
Nine hubs in Nepal, 2015

The real system, and it runs on meetings between people. The Nepali Army's own lessons-learnt review recorded organisations distributing relief randomly and uncoordinated, producing unequal distribution.

Academic disaster VRP
arXiv:1709.00162 — applied to this exact earthquake

Genuine optimisation over a road network — Fisher & Jaikumar two-stage, modelling a real volunteer group's 2015 operations. It begins with demand and road status already given as clean numbers.

So the gap is not the optimiser — that is solved. The gap is that nothing produces trustworthy structured input for it out of contradictory, incomplete field reports written by people who never spoke to each other. That layer is what we built, and it is why the answer is a language model rather than a better solver.

So we built a boundary, not a chatbot

Remove Gemma and there is no input at all — and the branch is the point: it decides whether to go and look, and the engine call is the only path to a plan.

03

The engine · and what it does not prove

Four stages, and one honest admission

01 · HANDOFF
B = max(sev, med, acc) × csys  ≤  1.0
Gemma's entire influence, one bounded scalar. UNKNOWN fields are excluded from the max — never read as zero. csys = clamp(0.55·R̄ + 0.25·D + 0.20·F − Pcontra − Pmiss)
02 · URGENCY
U = unmet-need + survival penalty (10.0) + B,   T(t) = 1 + 0.5(e0.3t − 1)
A dimensionless priority index, not a physical quantity. The model's ceiling is a tenth of one deterministic survival trigger.
03 · ROUTING
coste = de(1 + 0.06·max(0, τe − 1))
Capability- and closure-filtered Dijkstra over a real Nepal road graph. τ is terrain difficulty, 1.2 to 4.2, so the multiplier spans 1.012–1.192. Reported distance is the raw edge sum, never the weighted search cost. Measured: it flips no path here — slide 10.
Dispatch over that graph is capacitated vehicle routing — NP-hard, so we solve it as it is solved in practice: greedy urgency-ordered assignment, then a nearest-neighbour tour. A heuristic by choice; we claim no optimality.
04 · ALLOCATION
capped proportional → fixed point, normalized residual
Litres, kits and sheets are never summed on one axis — coverage is normalized per resource. Iterations with no recorded residual are omitted from the curve, not plotted as zero.
KKT DIAGNOSTIC

Three of the four conditions hold by construction, not by optimality.

λr is defined as the ratio stationarity tests, so that residual is algebraically zero for any input. Dual feasibility is a non-negative mean. Complementary slackness is zero by assignment.

Only primal feasibility carries information. An allocation delivering nothing to anyone passes all four.

The API ships independently_proves_optimality: false so nothing downstream can misread it. We would rather tell you than have you find it.

WHAT WE MEASURED, AND VOLUNTEER

We ran all 36 node pairs with the weighting on and off. Not one shortest path changes. Nine nodes and thirteen corridors is too sparse for a multiplier capped at 1.192 to flip a choice.
